# Architecture Decision Records (ADRs)

## ADR-01: Two-Tier Relational Ownership Enforcement
- **Status**: Accepted
- **Context**: `workflow.exports` records completed clip exports but does not contain an `owner_uid` column. Previous naive proposals added `owner_uid` to exports, which introduced table rebuilds and backfill migration risks.
- **Decision**: Publications reference `workflow.jobs(id, owner_uid)` via `fk_publications_job_owner` and `workflow.exports(id, job_id)` via `fk_publications_export_job`.
- **Consequences**: Provably blocks User A from publishing User B's export, and blocks publishing an export that was not generated by the referenced job, without altering existing tables.

## ADR-02: Two-Tier Append-Only Callback Ingress Logging
- **Status**: Accepted
- **Context**: Ingress ledgers referencing publications with `ON DELETE CASCADE` caused forensic security logs to disappear when publications were deleted. Furthermore, malformed JSON or unparseable event IDs could not be stored in structured tables.
- **Decision**: Decouple ingress into two append-only tiers:
  1. `workflow.publication_callback_ingress_ledger`: Raw HTTP bytes, raw body SHA-256, transport headers. Partitioned monthly by `received_at` with composite PK `(delivery_id, received_at)`.
  2. `workflow.publication_callback_processing_outcomes`: Parsed disposition and application HTTP responses.

## ADR-03: Fenced Outbox Leases with Monotonic Tokens
- **Status**: Accepted
- **Context**: Stalled background workers whose leases expired could wake up and mutate database rows after another worker claimed the task.
- **Decision**: Every claim increments a monotonic `fencing_token`. All state mutations (`RENEW`, `COMPLETE`, `RETRY`, `DEADLETTER`) strictly enforce `lease_owner = $worker`, `fencing_token = $token`, and `lease_expires_at > transaction_timestamp()`. Stale worker HTTP posts are neutralized by Publisher-side ledger deduplication.

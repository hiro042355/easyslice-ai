## Candidate contract

Schema tiktok_oauth contains states, connections, publication_grants. OAuth states bind the verified Firebase UID and session digest to app, environment, scopes, fixed canonical callback, issue/expiry time and atomic claim identifier. Only SHA-256 state digests are persisted. Maximum state lifetime is ten minutes. State and consent binding columns are immutable. Terminal transitions cannot reopen consumed, used or failed records.

Connections are unique per UID/app/environment and provider account per app/environment. Only encrypted ciphertext, twelve-byte AES-GCM nonce, sixteen-byte authentication tag and key identifier enter persistence. Active rows require a nonempty envelope; revoked rows must erase all three envelope byte fields. Encryption, AAD validation and key resolution remain server responsibilities; SQL envelope shape alone does not prove encryption. Sandbox/staging/production are explicit environment discriminators, never authorization switches.

Publication grants bind the owner/account/connection generation and canonical consent/media/Creator Info digest. Maximum lifetime is five minutes. The owner foreign key prevents orphan grants. Generation is intentionally retained on historical grants across reconnect; execution must atomically join the current active connection generation, account, owner and expiry before claiming. All sensitive state and grant predicates must include verified UID and app/environment. A shared runtime database role is not per-user authentication: application ownership predicates and the canonical Firebase boundary are mandatory. No claim of SQL-level tenant isolation is made.

Fresh DDL is intentionally not CREATE IF NOT EXISTS. Flyway history makes an unchanged second migrate a no-op; manually reapplying DDL fails instead of silently accepting incompatible objects. Foreign key/unique/check constraints and retention/owner indexes are explicit. No public table or schema grants are permitted. Runtime role receives USAGE plus SELECT/INSERT/UPDATE on these three tables, no DDL, no DELETE, no owner membership, no database creation. A separately authorized maintenance identity receives only bounded DELETE for retention. Exact existing identities and grants remain UNKNOWN and are not executed by this candidate.

## Retention and disconnect

Disconnect first invalidates outstanding states and grants in one transaction, then wipes the token envelope and marks the connection revoked. Reconnection replaces the generation; earlier grants become unusable even if still stored. Never erase or reopen pending evidence merely to retry a provider side effect. Expired/terminal OAuth rows can be deleted after an approved short operational retention window (proposed 24 hours); terminal grants after an approved reconciliation/audit window (proposed 30 days). These windows require Product Owner privacy approval. Cleanup batches must have a bounded LIMIT, DB timestamp predicate, explicit transaction and maintenance-only role. No scheduler is installed. Keep no token, raw OAuth state, authorization code, raw UID/open_id, or user content in diagnostic logs. History deletion must follow unresolved legal/privacy policy decisions.

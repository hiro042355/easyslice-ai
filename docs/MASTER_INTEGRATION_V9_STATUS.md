## Confirmed defects and corrections

1. `app/api/convert/route.ts` previously accepted unauthenticated unbounded multipart input, used predictable temp filenames and PATH FFmpeg, and returned raw process exceptions. `createMediaConvertRoute` now authenticates first, requires same origin, bounds actual multipart bytes (100 MiB file + 64 KiB overhead), ignores caller filenames, uses OS request-local directories, exclusive file creation, regular-file checks, packaged shell-free FFmpeg, cancellation/close-before-cleanup and safe errors. Output is bounded to 256 MiB; conversion has a 180-second deadline. This is direct uploaded data, not a persisted project: no project authorization is invented.
2. `cut`, `multi-cut`, `audio-energy` and `importYouTubeDirect` used the same job-derived temp root. Concurrent operations could overwrite and delete each other's input/output. Each now closes over its own `withRequestMediaWorkspace` lifetime. Owner/job/media relationship checks still precede materialization. Input download streams are exclusive-create/cancellable and count actual bytes (2 GiB); output/ZIP memory is bounded to 256 MiB. Multi-cut accepts at most 64 clips; request JSON is 128 KiB, audio JSON 8 KiB, cut multipart 128 KiB. Processing routes have 300-second operation deadlines. No retry was added.
3. Multi-cut duration and audio volume subprocesses lacked bounded lifetime. `captureMediaProcess` bounds internal stderr to 64 KiB, uses argument arrays/shell=false, kills on timeout/abort and settles only on child close. Duration inspection deliberately accepts a nonzero FFmpeg probe exit only after validating finite positive duration evidence. Volume detection preserves existing selection/boundary rules, not raw diagnostics.
4. `post-assets`, `script`, `ai-mv` and `ai-mv/cover` lacked authentication. `createGeneratedAssetBoundary` now gates authentication/origin/content type/body size before the existing prompt/DTO logic. The same boundary protects existing authenticated `ai-highlight` and local `summary`. `fetchGeneratedAsset` keeps fixed route-owned Google endpoints, applies the request deadline, bounds provider JSON to 12 MiB and discards raw failed-provider bodies. Cover output accepts only bounded raster image MIME/base64, not SVG/HTML. These are existing Gemini features; no live execution occurred and no OpenRouter activation was introduced.
5. Export retrieval previously buffered an unbounded GCS object. It now streams to a private exclusive request file, counts a maximum 256 MiB, validates it, materializes response bytes, then cleans up. Authorization and private/no-store response remain.
6. FFmpeg file/pipe protocol restrictions alone do not exclude local-file playlists. Media input paths now use explicit demuxer allowlists excluding HLS/concat/image sequences; canonical durable transcript/burn/import MP4 paths require `mov`. Synthetic disguised-playlist rejection is executable proof. This does not sandbox native codecs against a compromised same-account process.

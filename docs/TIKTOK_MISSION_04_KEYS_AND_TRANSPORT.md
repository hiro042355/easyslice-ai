# Mission 04 key and HTTP transport contracts

Code prepared 2026-10-09; no Production provisioning, credential retrieval or live requests. Server-only facades are lib/server/tiktokKeys/index.ts, lib/server/tiktokHttp/index.ts and lib/server/tiktokPublisherB7/index.ts. Independently testable core modules are trusted server composition ports, not browser/request-body APIs.

## Managed token custody

Production-intended envelope version 2 uses a cryptographically random 32-byte DEK per message, AES-256-GCM nonce12/tag16 and AAD including envelope format, verified Firebase UID, app/environment, TikTok open_id, connection generation, scopes, expiry and full pinned KMS version. KMS encrypts the DEK under the managed symmetric KEK with the same AAD. Only wrapped DEK, key version and authenticated ciphertext enter SQL. The managed KEK is never exported. DEK buffers are zeroed after use; JavaScript token strings are transient server values, never browser DTOs/logs.

Pure configuration parser requires NEXCUT_TIKTOK_TOKEN_KEY_PROVIDER=gcp-kms-envelope, NEXCUT_TIKTOK_TOKEN_KEY_ID=<explicit CryptoKeyVersion name>, and NEXCUT_TIKTOK_TOKEN_READABLE_VERSIONS=<explicit comma-separated versions>. No default key, env lookup, synthetic fallback or resource creation. ManagedTokenVault constructor validates version namespace/count/selection; startup checks name, ENABLED state and GOOGLE_SYMMETRIC_ENCRYPTION algorithm. PRODUCTION profile accepts only production-bound ciphertext; LOCAL_TEST accepts staging test data. Actual values were not inspected.

createManagedTokenVault(configuration, approvedSdkClient) requires an explicitly credentialed SDK client supplied by the future approved runtime. It does not instantiate ADC or infer authority from developer credentials. Uses the existing @google-cloud/kms dependency; no package version change. Get/encrypt/decrypt RPCs have 3-second deadlines and retry disabled. The existing creator-publication identity provider is MAC-based and must not be reused as a symmetric encryption key. Production target, WIF identity and symmetric key qualification are external prerequisites.

Minimal reviewed permission contract: cloudkms.cryptoKeyVersions.get plus cloudkms.cryptoKeyVersions.useToEncrypt and cloudkms.cryptoKeyVersions.useToDecrypt at the exact approved key. No key/IAM creation, destroy, disable or rotation mutation is performed. Actual IAM grants and principal must be approved and independently verified. Rotation procedure: separately authorize/provision a new enabled symmetric version, add it to readable versions, select it for new encryption, verify old ciphertext readability, retain old enabled versions until separately approved retention/re-encryption completes. Never automatically destroy or disable an old key. Provider failures emit only fixed READY/UNAVAILABLE classifications; no raw provider causes or resource/token fields. Startup fails closed without valid available keys.

SQL permits legacy version1 only for existing local regression compatibility; managed vault never falls back to it. There is no deployed TikTok token population being upgraded by this mission. Any later legacy adoption requires an explicitly reviewed migration/custody decision.

## Native transport and publication

The actual native fetch path is implemented, with DISABLED default. AUTHORIZED_NATIVE requires a trusted server release-authorization callback; it is evaluated before every I/O within the deadline. No environment, request-body option or browser flag creates that callback or activates deployed routes. All tests exercise native fetch only after replacing global fetch with a synthetic fixture. INJECTED_TEST uses an explicitly supplied fake function and rejects supplying global fetch as fake I/O. Actual live qualification remains NOT_VERIFIED.

Fixed OAuth/revoke/Creator Info/init/status endpoints on https://open.tiktokapis.com; no arbitrary base URL. Provider-issued FILE_UPLOAD destinations permit only the two documented exact upload hosts open-upload.tiktokapis.com and upload.us.tiktokapis.com with exact /video/ path and upload_id/upload_token binding. Unknown region/host fails closed until allowlist review. Redirects, cookies, embedded authority, query manipulation and extra headers are rejected. Media upload never receives API bearer credentials. Request and body reads are bounded by a 1–30000ms deadline and 1MiB response limit; cancellation aborts fetch and body processing. Errors expose classifications only. No automatic side-effect retry; ambiguous upload/init needs manual reconciliation, not another submission.

Publication delegates to accepted B7 validators/serializers/chunk/status/consent engines and verifies Firebase session, owned current account/generation, encrypted credential expiry/scope, fresh Creator Info, exact media checksum/settings and single-use durable consent. Separate bounded observation uses the existing status parser and immutable stored publication correlation; it does not reuse consent for a new init. Observation authorization is current owner/account scope, not expired posting permission. PUBLISHED/FAILED provider outcomes cannot be downgraded; processing/unknown never becomes success without a validated provider response. No public loopback service is opened.

Official references checked 2026-10-09: [Google KMS envelope encryption](https://docs.cloud.google.com/kms/docs/envelope-encryption), [KMS resource/version selection](https://docs.cloud.google.com/kms/docs/resource-hierarchy), [TikTok token management](https://developers.tiktok.com/docs/en/oauth-user-access-token-management), [TikTok media transfer](https://developers.tiktok.com/docs/en/content-posting-api-media-transfer-guide), [TikTok content sharing requirements](https://developers.tiktok.com/docs/en/content-sharing-guidelines). These contracts do not prove actual Production authority or approval.

Server-gated composition additionally binds the configured client key to the repository app ID and validates the managed vault execution/environment profile. An explicit runtime authorization callback is required before authentication, reads, DML and transaction commit. Its implementation must validate actual target/schema/IAM/migration receipts and Product Owner authorization; available credentials alone are insufficient. No current app factory supplies it. Callback-denial and JSON-like missing-callback cases are tested in a physically isolated local database, including a Production-labelled synthetic data profile; no real Production connection or credential is used.

## Required database objects and authority

Existing NONDEPLOYABLE_oauth_candidate.sql: hashed state and expiry/claim terminal transitions; owner/app/environment/openID connection uniqueness; ciphertext/nonce/tag/envelope_version/wrapped_key; one-use publication grants and immutable publish_id/provider_status correlations. Minimum application operations use SELECT/INSERT/UPDATE on these three tables plus database CONNECT/schema USAGE. No CREATE DATABASE/ROLE/SCHEMA/TABLE is required for a runtime job. Role metadata in disposable PG tests proves local least-privilege characteristics only; it is not Production migration authority.

Existing migration candidate is unversioned/nondeployable; fixtures are not a Flyway-applied release. Final ordering must use authoritative history and approved migrator execution identity. Production migrationIdentityAuthority, latestMigrationClassification, LOGIN_2_TABLE_CREATION_AUTHORITY and SEPARATE_MIGRATION_OWNER_REQUIRED remain UNKNOWN. No new migration/schema candidate was necessary for this local adapter. A future persistent distributed queue/media/history feature may require a separately reviewed candidate and migration-owner gate, not an invented version.

## KMS SDK and identity contract

Existing server-only createManagedTokenVault accepts a separately approved SDK with getCryptoKeyVersion/encrypt/decrypt, timeout3000/retry:null. It maps enabled symmetric metadata, wraps a random per-message AES-256 DEK with AAD, and unwraps under the explicit key/readable-version policy. The worker/local model uses the existing staging custody label LOCAL_TEST; that label is not permission to use Production keys. No SDK credential discovery/provisioning, IAM/key/API change or real SDK initialization was performed.

Required permissions are cloudkms.cryptoKeyVersions.get for startup metadata and cloudkms.cryptoKeyVersions.useToEncrypt/useToDecrypt for custody. CryptoKey Encrypter/Decrypter does not itself include version get; metadata permission needs separate approved least-privilege qualification. IAM is granted at key or enclosing resource, not an individual key version. These are documentation/source requirements, not observed grants. [Google KMS permissions](https://docs.cloud.google.com/kms/docs/reference/permissions-and-roles), [version get](https://docs.cloud.google.com/kms/docs/reference/rest/v1/projects.locations.keyRings.cryptoKeys.cryptoKeyVersions/get).

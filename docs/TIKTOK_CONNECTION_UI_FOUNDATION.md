# TikTok connection UI foundation

Entry: Workspace Home -> アカウント連携 -> /settings/connections. The page is server-rendered and always UNAVAILABLE until a separately authorized backend integration changes its producer. It reads no query, cookies, environment, storage or network response. Connect, reauthenticate, disconnect and publication buttons are disabled for every state. There are no event handlers, forms, OAuth redirects, API implementations, token custody or publication effects.

The typed future API contract specifies GET /api/tiktok/connection, POST /api/tiktok/oauth/start and POST /api/tiktok/disconnect. It defines no live adapter and contains no access/refresh token, client secret, OAuth state, session cookie, open_id, UID or credential-reference field. The future start response models server redirect navigation rather than exposing an authorization URL in application JSON. This mission does not implement that redirect.

Supported views: NOT_CONNECTED, CONNECTING, CONNECTED, REAUTH_REQUIRED, DISCONNECTING, ERROR, UNAVAILABLE. A bare response/lookalike handle cannot display CONNECTED. The private projection registry accepts only opaque handles minted by the trusted projection seam. The server-only facade is for a future authenticated backend producer; the pure core is the test injection seam. Projection is not an authentication verifier: the future producer must independently verify the Firebase session, current account ownership, app/environment and currentness, then provide those facts. This mission supplies no real producer, and the page never calls the projector. Booleans supplied by a browser or ordinary JSON are not proof of authentication and must never be used as the future producer's verification source.

Only a bounded validated account display name is projected. All credential fields and arbitrary errors are discarded. Missing, malformed, stale/mismatched verification facts, account identity or handle downgrade to UNAVAILABLE. Errors use a fixed Japanese classification map; React escapes rendered strings. Projection snapshots do not alias input. No connected fixture is present in application code; synthetic facts occur only in tests.

A future backend integration must require a verified current session and ownership, avoid Next.js/browser caching of account-specific evidence (no-store), enforce evidence freshness, and keep OAuth/token processing server-only. It requires a separate gate; defining this UI contract grants no authority to enable actions. Publication must additionally verify fresh Creator Info, granted posting scope/permissions, supported FILE_UPLOAD, explicit consent bound to current account/media/options, and independent publication authorization. A connected view alone grants none of these.

Tests render all states, parse the actual DOM with the existing jsdom runtime, and verify every button disabled. They cover missing backend, injected verified connected evidence, unverified/lookalike rejection, stale/mismatched context, safe identity, raw token/error exclusion, input mutation, fixed endpoints and transport/storage absence. A narrow declaration supplies only the existing jsdom constructor/document/close APIs used by tests; no dependencies or package versions are installed/changed. The isolated node_modules junction uses the existing clean dependency runtime.

Workspace changes only the account-navigation container and adds a fixed link. Authentication, workspace-flow, AI MV, review/autopilot behavior, YouTube/Bilibili logic, LOGIN-1 files, migrations, operator tooling and Publisher B7 remain unchanged. The new settings page contains no confidential account data and therefore needs no live authentication operation in its unavailable state; a future connected producer requires server-side authorization.

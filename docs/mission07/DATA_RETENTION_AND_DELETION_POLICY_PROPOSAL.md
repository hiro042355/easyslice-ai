## Common deletion contract, future work and decisions

All rows require Owner approval of exact period, purpose, legal basis, user notice, hold exception, backup window, regional storage, deletion SLA and request verification. Source video/AI output may reveal personal content; tokens authorize side effects; UID/openID/publishID/revision/log linkage remains personal metadata. Restrict access per user/app/environment, never return credentials/raw provider bodies in browser DTO. Ordinary decrypted-token JSON/inspection now redacts, but spreading fields still leaks and is forbidden in logs.

Disconnect currently invalidates outstanding state/grants and erases ciphertext/nonce/tag/wrappedDEK; it does not remove source media, past history, mapping metadata or remote TikTok posts. Revocation failure does not undo local disconnect. No integrated TikTok account-deletion cascade or remote-post deletion feature is proven. User account deletion must first authenticate/reconfirm ownership, stop new grants/operations, wipe tokens, isolate unresolved correlations, coordinate reference-safe owned object removal and record bounded deletion receipt. Do not infer Firebase account deletion automatically cascades into SQL/GCS/logs/backups.

Required database changes are a FUTURE versioned deletion-job/tombstone/expiry/hold/receipt design plus any refresh-expiry/index fields only after approved policy, authoritative version and migrator gate. No deployable migration or DDL added here. Required storage cleanup is bounded owner/reference-safe dry-run then approved executor; no shared key/prefix recursive deletion or signed-URL-driven arbitrary target. Background jobs need separate least-privilege identity, approved schedule/batch limits/locks/metrics/retry-safe receipts; no Production job installed.

Tests required before later implementation: cross-user/environment denial; disconnect/missing-key wipe; expiry != deletion; orphan path safety; reference/shared-object protection; in-flight and ambiguous-post hold; account-delete SQL/GCS coordination; interrupted-job idempotence; token/code/uploadURL log redaction; backup restore cannot resurrect usable credentials; TTL/clock boundaries. Existing disconnect/ownership/replay/unknown-status tests run now; speculative deletion scheduler tests are not claimed executed.

Backup/provider semantics: no instant physical erasure promise; approved backup expiry and post-restore tombstone reconciliation needed. Destroying an entire shared KMS version to delete one user is forbidden. Remote TikTok uploads/posts/account data obey provider controls; app disconnect is not provider deletion. Owner decides source24h vs saved-until-delete, metadata24h, diagnostics30d,history/audit90d proposals and alternatives; until then every period remains REQUIRES_PRODUCT_OWNER_DECISION.

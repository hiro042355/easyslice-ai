# Identity and secret management
Static existing FirebaseAdmin uses Vercel OIDC and Production-restricted WIF. Fresh staging three enabled service accounts and empty global WIF pool inventory are metadata, not effective runtime or Firebase permission proof. No new identity/IAM/impersonation/credentials/API enablement. Existing Firebase project/plan/authorized-domain inventory UNKNOWN; emulator/synthetic verifier not real sign-in.

Future minimum: a dedicated nonproduction app identity, approved Firebase project/domain/session boundary and token-revocation checks; approved workload federation where supported, or an explicitly reviewed restricted credential injection strategy if free host cannot federate. Never copy Production service-account credentials or reuse Production-bound trust by setting a staging env variable. Runtime trusts exact issuer/audience/deployment/environment and owner/session/app binding, not arbitrary request/JSON. Separate DB runtime DML identity, migration owner and encryption/rotation operator. Existing production verifier remains unchanged until this release.

Only encrypted project-scoped server secret bindings for Sandbox client secret, DB auth and any software KEK. No NEXT_PUBLIC secret, plaintext .env/file, dashboard screenshot/key/token, DSN logging or credentials in subprocess arguments. Process memory necessarily uses secrets transiently; host/admin access, logs, rollback snapshots and backups are additional custody boundaries. [Workers secrets](https://developers.cloudflare.com/workers/configuration/secrets/) documents encrypted binding values; [Render variables](https://render.com/docs/configure-environment-variables) documents injection/environment groups. Neither proves this actual account's access policy, KEK recovery or no-charge eligibility. No secret read/import/injection performed.

Rotate Sandbox client/DB/runtime/KEK credentials separately; validate new binding under gated nonprod evidence, drain stale pooled sessions, revoke old credential after recovery plan. Preserve readable envelope versions until ciphertext/backups retired. Redacted audit records actor category, operation, immutable version reference and fixed result, never secret/body/query. Provider admin/account access and backup restore policy owner-approved. Spark no-payment authentication may be suitable, but App Hosting/Functions features may require Blaze; no automatic billing switch permitted. OAuth starts from real normal authenticated same-origin browser only under later explicit gate.

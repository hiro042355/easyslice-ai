# PostgreSQL strategy
Persistent server-side PostgreSQL remains required for atomic state claim/consumption, unique account ownership, encrypted connections and immutable publication correlation. No switch to browser storage, Redis-only authority, Firestore, D1 or a Data API is justified. Existing injected pg Pool is sufficient as an interface; no new database abstraction/live connection added.

Candidates: existing qualified nonproduction database first, then Neon Free or Supabase Free only after actual account/plan/region/quota/payment/overage/recovery qualification. No existing Neon/Supabase account proved; no matching app/lib/infra/package source references found, which does not prove account absence. Staging SQL API disabled; no bypass/instance/user query. Render Free PostgreSQL's expiration/deletion/no-backup behavior cannot support the durable recovery plan; not selected.

[Supabase connection docs](https://supabase.com/docs/guides/database/connecting-to-postgres), accessed2026-10-09: direct free endpoint is IPv6; shared session/transaction pooler supports IPv4. Transaction mode cannot retain session state/prepared statements; migrations/dump use suitable direct/session connection. Require hostname/CA validation (verify-full or equivalent), not merely encrypted-but-unverified require mode. Small application pool and bounded timeouts; deployment instance count × pool size must fit actual provider connection limit. Actual target limit UNKNOWN; no paid IPv4 add-on. Store uses one client for BEGIN/operation/COMMIT, parameterized unnamed queries and rollback; no pooling change until real provider requirements are qualified.

[Supabase backups](https://supabase.com/docs/guides/platform/backups) recommends regular free-tier export/off-site backup; hosted automatic backups/PITR unavailable in free pricing. Neon accessible announcement has short six-hour restore, not an approved recovery guarantee. Free pause/quota restrictions must close connect/callback safely, never reopen state or report success on failed DB. Persistent data after account expiration/pause and export permissions must be owner-confirmed. No keepalive that defeats provider policy, no upgrade to recover data without approval.

Future owner/migrator: approve exact nonprod DB/history/checksums/schema/version and least-privilege runtime DML role; separate DDL owner. No runtime superuser/service-role DB credential, no Production data copied. Existing unversioned candidate remains NONDEPLOYABLE; no Flyway version invented. Runtime credential rotation must preserve bounded connection drain/recovery; old credential revocation separately approved. Back up encrypted tables plus role/schema definitions, without plaintext grants or KEK in dump; restore must prove decryptability and consumed-state safety.

Local PG18.4 private Docker regression is disposable tmpfs, no host port and cleanup; real durable remote DB still UNVERIFIED. Synthetic fixture DDL/DML executed locally, no Production/cloud SQL connection or migration. Retention periods and irreversible deletion remain unapproved.
